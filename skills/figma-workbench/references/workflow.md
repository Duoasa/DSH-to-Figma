# Inspect → construct → verify

Choose the shortest sufficient read path. An unknown target needs shallow `get_metadata({profile:"summary",depth:1})` discovery. For a known ID or selection, go straight to the necessary target details; do not always read both summary and full. Native properties usually need only bounded metadata; request `get_design_context` when CSS or implementation context helps, with `includeScreenshot:false` for structural work. Summary data is an index, not enough to reproduce a design. Search relevant resources only when the task uses them, and inspect the parent's layout before appending children.

Use query filters and bounded pages for discovery. Follow returned pagination and truncation information; a truncated tree is not a complete inventory. Once found, use explicit IDs and request detailed data only for the affected nodes. Do not repeatedly fetch the entire page, font list or variable collection for a small edit.

When a question asks for a few properties of named descendants under a known frame, a scoped read-only script can find those descendants and return exactly the requested values. Do not retrieve their entire surrounding subtree and several CSS contexts. For preservation during edits, snapshot actual existing labels/bindings; do not invent an expected value and then spend another call repairing that assumption.

For an existing design, return a short internal plan of the affected nodes and intended change. For a new composition, establish typography scale, spacing rhythm, colors, image needs and component reuse. Position new top-level frames away from existing bounds. Respect the requested product rather than forcing a visual template.

Build or modify a coherent subtree in one operation. For a known target and exact requested change, a script can validate current types/values before any mutation, abort on mismatch, load required fonts once, apply related edits, and read back affected properties. Do not add an entire context read solely to satisfy a fixed ritual. Add `await target.screenshot()` in that same operation when visual verification is needed. Avoid a separate model turn for each node. Return newly created IDs and reuse them in subsequent calls; do not recreate by name.

Use one composition screenshot after building, then a targeted post-fix screenshot if needed. The default screenshot already limits its longest edge to 1600 pixels; use `quality:"overview"` for composition and `quality:"detail"` or explicit `scale` when text/spacing requires closer inspection. Do not request another identical image just because a separate screenshot tool exists. Check overflow, typography, spacing, contrast and alignment. Validate component linkage and variable bindings structurally; a screenshot does not prove those relationships.

Local reads and writes are serialized per connected document. Do not run independent scripts concurrently on the same canvas. A fresh DSH Work session binds the only connected document automatically. Multiple documents require explicit selection. Existing bindings never silently switch after disconnect. The currently selected Figma node may change through human interaction; use explicit node IDs once discovered.

Do not turn a health check into an inventory of fonts, variables, all pages and screenshots. Load only the guide needed for the current operation, reuse already-loaded guidance, and skip repeated images when the relevant design has not changed. For diagnostics, use a performance cursor before/after the task to isolate this interval; default summary is enough unless investigating an individual call. These counters do not measure model token usage or total task time.

To measure an interval, save `performance.cursor` from `figma_status({compact:true,includeMetrics:true})`. Pass it as `metricsSince` on the later status call; add `metricsDetails:true` only for per-call entries. Check `performance.window.complete` and `dropped`. `completed` is the session total; `totals` sums only the returned interval. A cursor from another session or plugin run is rejected: establish a new baseline. Status/guide calls and model requests are excluded; provider usage and host traces are the source for end-to-end comparisons.
