# Figma to application code

1. If the frame is unknown, locate the smallest useful one with summary metadata. For a known frame, directly get its detailed context and one necessary screenshot, reusing a current image when available. The legacy result contains a node tree and root CSS. Use `semantic:true` for the bounded semantic projection and `includeCss:true` for descendant CSS when needed. Preserve `sharedStyles` references and inspect coverage/section plans; the local result does not claim to reproduce cloud-generated React output. Later structural reads should use `includeScreenshot:false` until a new image is needed.
2. Inspect the project's actual framework, components, tokens and conventions. `project_index` provides bounded component/token/SVG evidence; `project_match` prioritizes explicit mappings and reports ambiguous or stale candidates. Verify the actual source and rendered meaning before reuse. Map design semantics into existing conventions rather than introducing a new framework.
3. Read only the relevant variable definitions, modes, component context and local component links to preserve intent. Filter and page discovery results, then follow explicit IDs for details. Official Code Connect mappings are only available when the official backend supplies those tools.
4. Export real assets with `download_assets`. Use SVG for vectors and original image bytes for photo fills when appropriate. Do not draw a guessed logo or replace provided images with emoji. Exports land in `.figma/assets/<batch>/`.
5. Implement responsive constraints, semantic elements, accessible names and keyboard behavior in code. Translate auto layout into flex/grid when appropriate. Preserve deliberate overlaps rather than forcing everything into cards.
6. Compare rendered application output with the design screenshot using the host's available preview tools. Do not claim a visual match from compilation alone.

For native SwiftUI, map reusable Figma components into Views and state, typography into actual platform styles/custom fonts, and auto layout into stacks, grids and alignment. Assess dynamic type and safe areas. Do not assume a Figma pixel-perfect fixed frame is the desired behavior on every device.

Existing local component-to-code links use node plugin data. `project_mappings` is a separate workspace store with explicit identities, source-existence checks and revisions. Neither publishes Code Connect. Use `design_diff` for explicit, complete semantic baselines when tracking design changes across implementation work; reject incomplete captures and changed collection policies. See [local workflows](local-workflows.md).
