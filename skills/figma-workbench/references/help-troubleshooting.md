# 常见问题与排查

先回答用户的问题，再只查询解决该问题所需的状态。纯教程不要求先连 Figma。遇到故障可查 `figma_status({compact:true})`：当前 backend、DSH 插件版本、连接文档及 companionVersion、诊断信息。不能把磁盘上的包版本或窗口名称当成正在运行的版本。

## 连接与工具

| 现象 | 应检查什么 / 怎么处理 |
| --- | --- |
| 安装后 DSH 没有 Figma 工具 | 插件组件是否启用、是否运行；安装到了哪个 profile/home；重载组件，必要时重启 |
| 显示“等待 DSH 启动” | DSH 本地模式是否运行；是否同机；是否另一个宿主占用端口 |
| `bridge_port_in_use` | 找到占用同一桥接端口的重复宿主，确认后停用重复组件；不要随机终止不相关进程 |
| Figma 显示等待配对 / 密钥失效 | 使用当前 DSH 的 `figma_setup` 重新生成本机配对版；不要向聊天粘贴密钥 |
| 本地文档列表为空 | 在目标文件运行正确 home 对应的配套插件，保持窗口打开 |
| 要求 Work 会话 | 使用关联工作区的 DSH 会话；不是要求用户开启 Figma 开发者模式 |
| 多文件 / 旧绑定断开 | 列出当前连接，确认目标后明确绑定；不能悄悄改到另一个文件 |
| 官方 desktop 无法连接 | 在 Figma 开启官方桌面 MCP，并刷新连接；本地配套插件不能代替这个服务 |
| 远程注册 403 | 官方客户端/账号准入问题可能发生在授权前；不能用 Codex 已连接推断 DSH 已获准 |

保存的 bridge.json 或 CLI status 只能说明存在历史记录，不证明进程在线。未认证访问本地端点返回 401 是预期行为，不应据此关闭认证。

## 画布写入失败、超时或断线

若 `safeToRetryWithoutCanvasRead:true`，说明可修复执行前错误后重试；例如语法检查失败、已知不支持的同步 getter。若 false 或缺失，先检查画布和相关变量/组件，再决定补做，避免重复创建。

出现“执行中中断，操作不会重放”时：关闭并重新打开配套插件，确认目标文件，先读取可能受影响的节点。恢复连接不等于自动回滚。摘要、分页或实际被深度/预算截断的元数据不能解除保护；`profile:"full"` 和默认 profile 使用相同规则，需要对相关对象完整读回并检查 `recovery.cleared`；不能拿无关节点的结果当作成功证据。

## 新增 Dark 模式报 `Limited to 1 modes`

这是当前编辑器拒绝新增变量模式的限制。文件里已有多模式集合，不代表当前账号或文件还能给这个集合、新集合继续加模式；已有模式列表也不等于可新增数量。先读取目标集合的真实 ID、已有模式和相关变量，已有 Dark 就复用其 modeId，不能反复调用 `addMode('Dark')`。

新增模式应安排在变量赋值、组件和画布修改之前，单独尝试。脚本只能明确捕获原生 `Limited to N modes` 模式数量限制并返回失败状态，其他异常仍应报错。具体隔离调用见 [组件与变量指南](components-variables.md#variable-mode-limits-and-a-single-mode-fallback)。

如果上一轮已经报错，且 `safeToRetryWithoutCanvasRead` 为 false 或缺失，先检查集合模式、变量值、别名和受影响节点的绑定，再对相关目标执行完整或默认 profile、无分页的 `get_metadata`，并检查 `recovery.cleared`。变量读取不能单独解除不确定写入检查；元数据读取也不能证明变量未被修改。确认实际状态后再补做，不能直接重放上一轮或立即执行另一套写入脚本。

若需求允许用独立深色主题，可建立单模式的 Dark 专用集合，在它的实际默认 modeId 下设置深色值和别名，并把指定深色节点重新绑定到这些新变量。不要把现有 Light 值改成深色，也不要为了深色实例改写共用的 Light 组件。仅创建新集合或设置显式模式不会自动转移原来的变量绑定。完成后核对两套变量、绑定与外观，并说明这是独立单模式方案；它不等同于原集合的原生 Light/Dark 切换。

## 字体、素材、截图与性能

- 字体缺失：查实际可用字体和字重；用户同意替代后再换。不要私自转成图片。
- 素材路径被拒绝：素材工具只读当前 Work 工作区。检查真实路径，必要时经授权复制到工作区。
- 导出过大：拆批、降低倍率或缩小节点范围，不无限重试同一批。
- 模型看不到截图：检查当前模型是否支持图像输入；有导出文件不代表模型完成视觉检查。
- 大文件很慢：缩小页面/节点范围、复用已知 ID，避免反复扫描整个文件、列全量字体和截相同图片。
- 性能统计：插件统计的是当前 Work 会话内的画布调用，不是总 token、总任务耗时或全部工具次数；不能用它替代提供方账单。

## “只读”和不支持的 API

能力探测是只读的，不代表 local 插件禁止编辑。Motion 的某些集合不可直接赋值，需要专用方法。官方 desktop 模式以其实际目录为准；原生 Specs、Shader、视频编码等取决于当前编辑器实际开放的 API，Code/Make 云端任务仍需官方工具。视频探测显示 unknown 可能仅表示还未尝试原生编码，不能据通用 `exportAsync` 接口断言支持或不支持。对不可用功能说明具体边界，不能通过改 capability 标志伪造支持。

## 新工作流的常见边界

- 新工具或参数提示 companion 不支持：先确认 featureVersion 5，运行 `figma_setup` 后关闭并重新运行配套插件，再按状态重新选择文档。
- 设计基线拒绝保存：检查是否有截断、字段读取错误或采集策略变化。缩小到完整目标，或恢复原采集策略；不要强行把部分结果覆盖为基线。
- 映射显示 stale：核对当前 Work 工作区和真实源码路径，显式修复并传最新 revision；名称相似的候选不会自动替换已有映射。
- 网页捕获找不到浏览器：安装 Chrome/Chromium/Edge，或配置 `DSH_FIGMA_BROWSER_EXECUTABLE`。插件不会自动下载浏览器，也不会读取现有登录配置。
- 批量修改失败：阅读恢复报告里的失败和残留字段，检查目标后再继续。`operation_status` 可检查原操作，但不会重放或解除画布核对要求。

参数与例子见 [本地工作流](local-workflows.md)。

## 用户可提供哪些诊断信息

插件版本、DSH 组件状态、当前 backend、文件类型、简短错误、发生前的操作、是否存在部分修改、相关节点 ID，以及不含秘密的界面截图。避免收集配对 code.js、配对 ZIP、bridge-token、OAuth 状态或整个用户配置目录。

回答示例：“当前是在 local 模式，但连接文档列表为空。请在目标 Figma 文件运行当前配对目录的 Local 插件；窗口显示已连接后，我再确认文件身份。无需复制密钥。”

## Code Layers（代码层）

本地读取已有代码层会标记 `opaque:true`，表示只能读取它暴露的名称、位置、尺寸等外部属性，不能读取或修改内部代码、子层。这不是读取失败，不要反复重试。截图与导出以该节点实际支持为准。`FIGMA_CODE_LAYER_UNAVAILABLE` 表示当前编辑器未提供本地创建入口；可以按需求创建普通可编辑图层，但不能把它说成可运行代码层。FigJam 代码块是另一种节点。
