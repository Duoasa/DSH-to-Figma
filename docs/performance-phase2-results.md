# 0.2.5 自然语言任务对照结果

2026-10-26，在真实 DSH 与 Figma 中对比 0.2.4 和 0.2.5。每类任务、每个版本各运行三次，共 18 次。新版 9 次均满足任务要求，旧版 7 次通过；旧版另外两次把已经存在的空集合判断为不存在。这里只验证这三类任务，不能据此宣称所有设计操作均已优化。

## 环境与方法

- DSH 0.2.1-rc.3，Figma 126.9.16，macOS；模型界面显示 DeepSeek-V4.1-Flash /1017 /High，日志为 `deepseek-official / deepseek-flash / high`。
- 旧版代码 `daaf77d`，最终新版代码 `d67a9d6`。最终实机状态确认宿主插件和 companion 都为 0.2.5。
- 每次新建会话，模型自行决定工具和参数。新旧版本九组提示词的 SHA-256 全部相同；提示词没有指定工具名、读取档位或分页参数。
- 使用专门创建的合成测试页：1920×1080 画板、每个画板 12 个按钮实例、24 个双主题变量、一个已有的空集合。三个编辑任务使用相同内容的独立画板。换版本前核验并恢复实例圆角，保留相同起点。
- 从宿主持久化会话中提取真实供应商 usage，包含任务内错误、补读和恢复调用。耗时为 `turn/start` 到 `turn/end`，不含会话之间等待。素材准备、状态恢复和最终独立核验不计入任务。

完整口径见[测试协议](natural-language-benchmark.md)，脱敏后的每次用量、工具轨迹、提示词模板、哈希和结构核验见[原始结果 JSON](evidence/performance-phase2-natural.json)。没有公开用户会话日志、文件标识或配对凭证。

| 自然语言任务 | Token：旧 → 新 | 耗时：旧 → 新 | 模型请求：旧 → 新 | 工具调用：旧 → 新 | 满足任务要求：旧 → 新 |
| --- | --- | --- | --- | --- | --- |
| 已知画板，读取标题字体及一个按钮的属性与绑定 | 121,172 → 116,490（−3.9%） | 12.700 → 14.725 秒（+15.9%） | 7 → 7 | 8 → 6 | 3/3 → 3/3 |
| 确认已有空集合，报告模式及变量数 | 58,277 → 44,447（−23.7%） | 7.424 → 6.136 秒（−17.3%） | 4 → 3 | 4 → 3 | 1/3 → 3/3 |
| 修改 12 个实例圆角，保持标签、组件关系和变量绑定，并检查截图 | 167,631 → 124,233（−25.9%） | 26.890 → 17.088 秒（−36.5%） | 9 → 7 | 9 → 7 | 3/3 → 3/3 |

空集合任务同时改善了正确性和消耗，但旧版较低的部分耗时来自错误回答，不能把两者视为相同质量的完成结果。已知画板读取的工具数减少，耗时却没有稳定改善，本轮不将该场景判为速度优化成功。

九次任务合计，旧版 → 新版：

| 指标 | 0.2.4 | 0.2.5 |
| --- | ---: | ---: |
| 总 token（含缓存读取） | 1,001,501 | 840,051 |
| 未缓存输入 token | 54,116 | 53,861 |
| 缓存读取 token | 932,352 | 772,736 |
| 输出 token | 15,033 | 13,454 |
| 任务耗时之和 | 145.519 秒 | 130.277 秒 |

合计 token 减少约 16.1%，主要差值来自缓存读取；未缓存输入仅减少约 0.5%。这不是费用节省率，未按各类 token 的价格换算。三次样本不足以推断稳定的速度或 P95，且运行顺序为先旧版、再新版，没有交替随机化，缓存与网络波动仍会影响结果。

## 正确性与发现的问题

最终另行执行只读脚本，核对 4 个画板的 48 个实例：三个编辑画板的 36 个实例圆角为 12，原画板的 12 个实例仍为 8；标签、主组件引用与填充变量绑定保留，主组件圆角仍为 8。空集合、24 个主题变量及双模式别名检查通过。三个编辑任务都返回了真实截图；结构检查与图片检查分别完成，用户的视觉验收仍需试用。

本轮还在真实任务中发现节点包装器未实现 `has`，导致 `'children' in node` 为假，模型遍历得到零个实例后反复补查。0.2.5 已修复并增加回归测试。修复前的三次探索记录保留在 JSON 的 `exploratoryCandidate`，不混入最终 18 次对照；另有一次输入节点 ID 被界面错误录入的试跑被排除。最终三次重复没有删除表现较差的样本。

模型侧仍有两个明确问题：新版第二次读取任务两次漏写脚本外层 `return`，返回 `null` 后重试，相关成本已计入；第三次读取额外给出的色值为 `#2563EA`，实际四舍五入应为 `#2563EB`。后者不影响任务要求的变量绑定结论，但不能称所有回答完全无误。工具错误数为零也不表示没有无效调用。

最终核验还实测了会话区间统计：游标从 0 到 1，仅包含一次 `use_figma`，窗口完整、无丢失；宿主调用约 30.978 毫秒、companion 执行 18 毫秒。它们是嵌套的插件执行时间，不是模型端到端耗时。`nodeCount:0` 表示没有调用内置节点快照序列化，不代表脚本没有检查这 48 个实例。

## 代码验收与后续

`npm run test:all` 通过 62 项测试及 DSH 原生服务 smoke；合成查询基准通过 7 次重复。自动化原生服务 smoke 使用仓库依赖 0.2.1-rc.2，上述自然任务使用实际桌面宿主 0.2.1-rc.3。独立代码复核未发现阻断问题。

本轮完成空集合与覆盖范围、实际运行版本、按会话的区间诊断、自适应读取策略，以及节点属性检测修复。变量和组件的专用批量创建/修改接口、跨调用缓存、并发导出仍属后续阶段；当前相关操作继续使用有范围约束、前置检查和修改后回读的脚本。下一轮读取优化应针对模型缺少返回值和重复获取属性的真实轨迹，继续按完整任务成本验证。
