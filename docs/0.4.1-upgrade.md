# 0.4.1 全面升级记录（未发布）

本轮以 0.3.5 为基线，按 Codex Figma 工具集与 Figwright 对照分析开发 0.4.1。默认仍走 Figma 本地插件，desktop/remote MCP 的动态工具、资源、提示词与 OAuth 路径完整保留。本次不做后续本地稳定版的专项本地化、授权或分发改造，也不发布 GitHub Release。

## 实现对照

### 同步节点查询兼容

复用本地脚本已有的 AST 解析，将顶层或异步函数内、明确属于 Figma API 的 `getNodeById(...)` 调用适配为 `(await getNodeByIdAsync(...))`。不新增提示词、工具调用、画布读取、重试或第二次解析；普通字符串、同名用户对象以及同步回调/参数默认值保持原样，不自动改变函数返回类型。官方 MCP 路径不改写。2026-11-09 在真实 Figma 测试文件中一次调用完成两个临时节点的创建、同步写法查找、删除及空结果验证，页面未切换，无错误和恢复读取；244 项回归及实际 DSH 0.2.2-rc.1 宿主测试通过。

### 实测修正：本地页面上下文

本地 `use_figma` 保留执行开始时编辑器的当前页、选区和视角，不再像云端隔离执行器一样自动复位到第一页。用户选中参考 UI 后，先用 `get_selection` 获取节点和页面 ID，后续使用显式 ID；只有目标需要时才调用 `setCurrentPageAsync`。脚本主动改变页面、选区或视角仍然生效；用户在两次调用间主动切页也会被尊重。官方 desktop/remote MCP 继续按其实际协议运行。

2026-11-09 实测出现的 `in addMode: Limited to 1 modes only` 来自 Figma 当前文件的变量模式限制；既有多模式集合不表示当前仍有新增权限。随后一次写入被不确定结果保护拦截，未下发到 Figma；读取状态后采用独立深色变量集合的方案完成。保留这一保护，补齐具体原因和恢复指引，避免将套餐限制误判为断线或通过错误文案推断脚本没有先前写入。

本地目录由 19 项扩展为 40 项工具，其中 4 项只操作当前 Work 工作区；另有 5 项连接、设置和指南工具。数量不代表与官方 44 项工具完全等价。

## 版本一致性

- `package.json` 为唯一包版本来源，当前为 **0.4.1**。
- 构建生成的通用 Figma 插件内嵌同一公开版本；配对包 bootstrap 和说明文件使用同一值。
- Figma 窗口标题、设置面板与 `figma_status.documents[].companionVersion` 显示运行中的真实配套插件版本。
- `featureVersion:5` 是功能协议版本，不是产品版本；manifest 的 `api:"1.0.0"` 是 Figma API 版本，不能改成产品版本。
- 安装更新后的 DSH 插件后，运行 `figma_setup` 更新配对文件，关闭并重新运行 Figma 配套插件；已打开的旧运行实例不会因磁盘文件变化自动升级。

## Issue #19 / #13 修正（2026-11-09）

- #19：恢复判断与查询能力门槛解耦。默认/full profile 都接受完整的目标子树；摘要、分页、深度或预算截断不解锁。只在写入结果不确定时，复用已有元数据响应检查并返回 `recovery.cleared`、原因和范围；正常路径无额外调用/扫描/恢复提示。子树读回不代表整份文件或变量全部核对，仍需核对实际受影响资源后补做。
- #13：CODE_INSTANCE 的元数据、语义上下文及 tree 显式标为 opaque，避免访问其内部子层。已有握手/能力探测只检查构造函数是否暴露，不执行探测写入。已知未暴露时，现有语法预检拒绝直接构造调用；动态调用失败仍保留部分写入保护。截图/导出按实际节点能力处理，不假设可用。
- 桌面/远程 MCP 保留原始工具 schema 和行为；本次修正不新增云端依赖。

## 设计参考（0.4.1）

插件保留原连接区和底栏，新增默认收起的「设计参考」。选中一个画板、组件、分区或组，展开后点「绑定当前选区」；左侧显示名称与「解绑」，右侧显示小缩略图。规范引用只显示名称。绑定与解绑均可通过 DSH 操作。

- `set_design_reference({nodeId})` 绑定画板；缺省 nodeId 时要求当前恰好选中一个对象。
- `set_design_reference({kind:"spec",nodeId})` 引用规范画板/文字；也可传 `name` 和 `content` 保存最多 10000 字的命名规范。
- `get_design_reference()` 读取绑定；需要图片时显式传 `includePreview:true`。节点引用按 ID 跟随源对象，详细样式按需读其 nodeId。命名文本规范可再次 set 修改。
- `clear_design_reference()` 或 UI「解绑」只清除引用，不删除源画板或已生成页面。

绑定保存在当前文件的插件数据中，重开插件仍保留。改名后按 ID 识别；源对象删除后显示失效，不自动换成其他画板。打开栏目/显式读取时刷新源状态，正常操作不扫描画布。缩略图最大边 160px，仅展开或明确请求时导出。折叠不读取详细规范；`figma_status` 仅带上次已知的简短描述，不自动注入全文。不创建云端 Specs、不锁定历史快照，也不主动把规范同步应用到已生成 UI。

### 双向参考变更通知

Figma UI 与 DSH 工具的绑定/换绑/解绑共用文件内状态。插件 UI 将小型描述同步到本机桥接；DSH 的操作结果也立即同步回 UI。通知通过宿主动态上下文在下一次模型请求前刷新，明确新参考替代旧参考，或已解绑、不再沿用旧规则。不会中断已发出的模型请求或正在执行的画布操作。

通知仅含文件身份、参考名称/类型、节点 ID、版本和一句使用规则；不含截图、完整 UI 或规范正文。正常步骤只读取内存中的当前文档描述，不调工具、不扫描画布；宿主将变化的上下文记录到会话，未变的快照不重复追加。多个文档按当前 Work 绑定隔离；断开或工作区改变时不沿用旧状态。消息序号阻止迟到心跳把新绑定覆盖回旧绑定。旧宿主无动态上下文接口时使用同样简短的当前状态提示词段落。

设计参考栏目保持原结构：左侧线性图标与名称，右侧线性展开箭头，展开时箭头向上。
