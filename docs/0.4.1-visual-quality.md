# 0.4.1 视觉质量与恢复优化

工程长期最高准则：**在保证 UI 质量的前提下，让验证更容易被执行，让恢复更便宜，同时保持正常操作轻量。**

用户未明确复刻程度时，DSH 在绘制前一次澄清“快速成稿 / 均衡还原（推荐）/ 精细还原”；已有上下文明确时直接沿用。验收以约定目标为准，不在工具正常调用中增加询问。

| 能力 | 行为与边界 |
| --- | --- |
| `compare` | 本地参考图与节点渲染的并排、叠加、采样色差、候选边界及显式区域尺寸差；需要正确裁剪和区域映射，不自动宣布视觉验收通过。 |
| `use_figma.verify` | 按需回图；支持已知 nodeId 或从绘制返回值提取 ID。绘制成功、截图失败分开报告，只补截图。 |
| `rollback` | 显式回收失败操作中记录的、未改变的可丢弃新建子树。依赖节点、已有内容、不确定归属和后续修改会跳过；不是事务回滚。 |
| `use_figma.readOnly` | 受限解释器执行查询和本地计算，不运行任意 JavaScript；读取失败不新增写屏障，也不解除旧的不确定写入。 |
| `resolve_fonts` | 批量查询实际可用字体，短时缓存，明确回退；不内置字体、不承诺字形覆盖。 |
| `figma.icon` | 27 个 Feather 常用矢量图标，本地生成；保留 MIT 许可。 |
| 错误修复动作 | 沿用 suggestedAction/messageHuman/reconcile，补 FILL、字体和只读属性提示；区分当前调用未开始与前一笔仍待核实。 |

产品与插件 UI 版本仍为 **0.4.1**；新增能力协议为 **featureVersion 6**。本地链路优先，官方 MCP 路由保持独立，不伪造云端能力。npm 发布仍暂停。

验证记录：267 项自动测试通过；DSH 0.2.1-rc.5 与本机 0.2.2-rc.1 原生宿主测试通过（Figma 为模拟运行时）；三轮有界查询 fixture 基准完成。真实 Figma 全流程与视觉验收尚未完成，不以自动检查替代。2026-11-10 用户另行授权完成修改后推送并合并 main；合并不代表实机视觉验收通过。

## 复刻档位

| 档位 | 用户说明 | 验证标准 |
| --- | --- | --- |
| 快速成稿 | 更快看到结果，细节允许近似。 | 保留主要布局、信息层级和整体观感；回图修正明显错位、遮挡和溢出。 |
| 均衡还原（推荐） | 兼顾速度与还原度，适合大多数任务。 | 布局、比例、配色、字体层级和关键组件接近参考；对照修正影响观感的差异。 |
| 精细还原 | 投入更多时间，尽量贴近参考细节。 | 在字体与素材可用范围内细化间距、尺寸、图标和颜色；分区域修正并复查。 |

三档均需视觉验证；不承诺固定耗时、还原百分比或像素级一致。档位由 DSH 对话澄清，插件 UI 不增加弹窗或配置，正常调用不增加检查。

## 布局意图与轻量验证

三档均以合理结构和预期编辑行为为底线。Auto Layout、固定尺寸/定位、约束/锚点、叠层及图层锁定按场景组合，不强制某一种技术，不按覆盖率评分。锁定防误改，不替代布局关系。精细档应修正有意义的视觉偏差，但不为细微像素差破坏合理结构。固定展示不强制响应式，需要适配的区域才测试内容/尺寸变化。

若用途会影响布局且上下文未说明，开始前一次确认“固定尺寸展示 / 随窗口或内容调整”，可与还原档位合并询问；由 DSH 选择实现方式。

`verify.layout:true` 在同次回图中按需读取目标和至多 19 个直接子节点的布局、约束、定位及锁定属性；不遍历整页、不改变尺寸或解锁。报告只证明读到了这些属性，明确标记行为未测、验收未成立。`compare` 根据真实父级布局和绝对定位状态给出候选修改属性，保留固定/锚定/覆盖布局的合理性。
