日期：2026-11-10。产品版本保持 0.4.1；修正后的图像对照要求配套协议 7，其余已有协议 6 功能不提高门槛。完成隔离验证后，已按用户要求更新日常 DSH 安装与本地 Figma 配套插件，并重新加载两端；未发布 npm/GitHub Release。

## 修改与边界

- 将未明确的复刻目标澄清提前到详细测量之前；按完整区域组织绘制并保留节点 ID，在关键完成点合并回图。依据目标和观察到的缺陷继续验证，不固定轮数，不强制 Auto Layout，不降低布局/视觉质量标准。
- 对照默认使用节点主体边界，排除外扩效果。`bounds:"render"` 明确包含阴影/外扩描边并返回主体偏移；参考图须选择相同区域。读取已有边界和 PNG 尺寸，不增加画布遍历、不修改节点。保留纵横比，不通过拉伸消除比例差。
- 复用现有脚本解析，拦截确定的内置图标名错误和已知 Figma 节点上的 `strokeDashes` 写入；后者提示使用 `dashPattern`。普通 JSON、遮蔽的 figma 变量及无法证明的动态接收者不被静态规则误判。运行时属性错误标明属性/节点，保留部分执行语义。
- `get_metadata({nodeId,profile:"full",depth:10,responseMode:"recovery"})` 在完整性检查之后投影为节点清单，保留身份、父级、几何、部分布局属性和文本片段。完整属性仍按需读取；清单不推断创建归属，也不假称验证了省略的属性。深度/预算不足、摘要、分页和变量资源保护规则不放宽。
- 离线会话分析区分工具耗时之和、工具时间区间并集、提问等待和工具外耗时；后者不能直接解释成纯模型计算。没有新增运行时遥测或正常操作提示。

导出使用公开的 [Figma ExportSettings](https://developers.figma.com/docs/plugins/api/ExportSettings/)；`useAbsoluteBounds` 与真实编辑器的导出结果均已核对。

## 真实 Figma 编辑器验证

在既有独立 Smoke 测试文件中运行本地隔离宿主与新版测试配套插件，未替换正式配置。仅创建两个 320×180 临时画板及其子节点。

1. 无阴影参考图与有阴影节点按主体比较：实际输出 320×180，区域坐标差和采样色差均为 0；查看了真实并排图，两侧主体重合。
2. 含阴影比较：实际导出 368×228，主体相对导出区域偏移 (24,16)，显式区域坐标差和采样色差均为 0。普通截图仍保留外扩阴影。
3. `figma.createFrame(); figma.icon('refresh')` 在宿主预检失败，返回源位置、图标替代动作和 `not-started`，未派发脚本。
4. 动态属性测试先将临时矩形 x 改为 1，再写入 `strokeDashes`。错误标明正确属性和目标，报告 `partial-or-unknown`；没有自动重放或删除修改。
5. 深度 0 的精简恢复读取仍返回 `cleared:false`；完整子树读取后为 `cleared:true`，清单准确显示 x=1。之后仅修正目标节点，使用 `dashPattern` 成功并回图；已检查该真实渲染。
6. 临时节点已按已知 ID 清理并读回确认不存在；测试全过程页面保持原页面。关闭测试插件、停止隔离桥接，恢复用户原文件标签与连接。

以上证明定向功能路径，不等于复杂 UI 复刻质量或用户视觉验收。

## 安装后的实机观察与限制

- 日常 DSH 的只读健康检查返回宿主/配套版本均为 0.4.1、featureVersion=7、busy=false、needsInspection=false；新工具定义已包含 `compare.bounds` 和 `get_metadata.responseMode`。
- 后续自然任务实际使用了节点边界对照与精简局部恢复读取，部分写入恢复后继续执行。原始会话、截图和本机配对凭证不随源码提交。
- 工作流指引不等于模型行为保证：仍观察到延迟澄清、快速档位下细节精修、自行导出后重新处理阴影偏移，以及固定尺寸与内部布局行为混淆。本次未宣称这些策略问题已经解决。
- 受限只读执行仍不支持普通执行路径的全部方法；实测出现 `findAll` 属性访问被拒绝及 `query` 链不可调用。缩小检查范围后成功，不代表原完整检查已通过；该能力差异留待后续修复。
- 用户认为当前模型的实际复刻速度与质量可以接受。不同任务和模型的观察不能当作控制变量基准；后续优化应保留有效分析与视觉验证，重点消除明确错误和重复工作。以达到认可质量的时间、用户介入和后续编辑行为衡量，不以调用次数单独判断效率。
