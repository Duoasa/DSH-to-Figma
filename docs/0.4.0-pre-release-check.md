## 原生文件身份修复与实测：第二阶段（2026-11-04）

第一阶段关于当前环境无法返回真实 key 的判断已查明根因：配套 manifest 漏了 `enablePrivatePluginApi`。Figma 官方说明该配置也适用于本地开发插件：[manifest 文档](https://developers.figma.com/docs/plugins/manifest/#enableprivatepluginapi-boolean)、[fileKey 文档](https://developers.figma.com/docs/plugins/api/figma/)。已启用此配置；编辑器原生 key 优先，手工文件链接仅作缺失时的备用，不能覆盖原生身份。

在相同的已安装 DSH Work 与真实 Figma 文件复验，没有填写手工文件链接：

- 首次重开得到真实 key `REDACTED`，明确绑定连接 `39d25a4f…`。
- 暂停、关闭并重新运行配套窗口后，新连接为 `f57836fe…`，真实 key 保持一致，`bindingMatch` 为 **same-file-key**。

- 由此解决本机本地开发配套插件“只能按名称猜测文件”的根因。仍不自动重放中断操作；多个相同 key 的活跃连接需明确选择。重启 DSH 后的 Work 绑定持久化不是本次变更范围。

原始证据：本机 `output/prerelease-040/live-native-file-key.json`。修复后完整测试为 **113 项通过**，另有配套打包配置及原生 key 不被手工链接覆盖的回归检查。更早章节的 111 项统计与缺少 key 的结果属于当时构建；以本阶段结果为准。本次更新本地构建和本机安装，未发布或推送。
